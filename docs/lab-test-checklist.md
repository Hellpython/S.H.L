## 12. 거리별 반복 시험

RSSI는 거리 값이 아니다. 같은 거리에서도 방향·손·가방·사람 몸에 따라 크게 달라진다. 이 시험은 "어느 범위에서 감지가 안정적인가"를 보는 것이다.

### 12-1. 1회 시도 절차 (매회 반드시 처음부터)

1. 송신 ESP32(키링) 전원 OFF
2. 수신 장치가 **WAITING**이고 **LED OFF**인지 확인
   - 직전 시도가 WARNING이었다면 `[STATE] WARNING -> WAITING`과 `[LED] OFF` 로그가 찍힐 때까지 기다린다.
   - `[ALIVE] ... state=WAITING`이 최근 20초 안에 찍혔는지 확인한다.
   - 확인되면 시리얼 모니터의 **마지막 줄 위치를 표시**한다(예: 빈 줄 입력, 메모). 이후에 나오는 로그만 이번 시도의 로그다.
3. 송신 ESP32 전원 ON (시각 기록)
4. 표시한 위치 **이후에 새로 찍힌** `[RX] t=...ms keyring=<번호> rssi=...` 로그 확인
5. `[STATE] WAITING -> WARNING`, `[LED] ON` 로그와 실제 LED 점등 확인
6. 판정 기록

판정 기준:

| 판정 | 조건 |
|---|---|
| 성공 | 2단계 초기화 확인 + 4단계 새 RX + 5단계 WARNING·LED ON 모두 확인 |
| 실패 | 초기화는 정상이었고, 판정 제한 시간 안에 새 RX 또는 WARNING·LED ON이 없으며, `[ALIVE]`는 계속 나왔고, 아래 근거리 대조 시험은 성공 |
| 무효(재시도) | 2단계 초기화가 확인되지 않음(이전 WARNING이 남아 있음, LED가 켜져 있음 등), 시도 중 `[SCAN ERROR]` 발생 또는 `scan_errors` 증가, `[ALIVE]`가 20초 넘게 끊김, 수신 장치 재부팅, 근거리 대조 시험도 실패 등 |

**근거리 대조 시험** (새 RX가 없을 때마다): `[ALIVE]`가 계속 나와도 스캔 시작 뒤의 일부 실패는 감지하지 못한다. 그래서 "멀어서 못 받음"과 "수신 장치가 신호를 못 받는 상태"를 로그만으로는 완전히 구분할 수 없다. 새 RX가 없으면 키링을 켠 채로 약 1m까지 가져와 새 RX가 나오는지 본다.
- 나오면 → 원래 거리의 시도는 **실패**
- 안 나오면 → 수신 장치 이상 의심, 해당 시도는 **무효**. roadside를 리셋(EN)하고 2단계 초기화부터 다시 한다(리셋했다는 사실도 기록)
- 수신 장치 상태를 확인할 수 없으면 **성공으로 처리하지 않는다**.

- 이전 시도의 WARNING이 남아 있는 상태에서 LED가 켜져 있어도 **성공으로 세지 않는다**.
- 무효·실패는 반드시 원인을 적는다. 원인을 모르면 "원인 미상"과 해당 시리얼 로그를 남긴다.
- 판정 제한 시간은 시험 전에 정해 적어 둔다(시험 절차상 값이며 성능 기준이 아니다): ____ 초

## X1. USB 분리 → 신호 소실 타임아웃 (1회 관찰, 2026-11-27)

맥북 시각은 기록기(`[HOST]`)가 XIAO USB 포트 소실/생성을 감지한 시각(약 0.2초 주기 확인). 원문: `docs/logs/2026-11-27-roadside-usb-onoff.log`

| 항목 | 기록 |
|---|---|
| XIAO USB 분리 (맥북 시각) | 19:48:28.682 |
| 마지막 `[RX]` | 19:48:29.173 (`t=39639ms`, rssi −75) — 분리 *후* 시각인 이유: `[RX]` t는 스캔 종료 시각 |
| `[LED] OFF` + `[STATE] WARNING -> WAITING` | 19:48:32.406 (`t=42897ms`) |
| 마지막 `[RX]` → WAITING (보드 시각) | **3258 ms** (설정 `kSignalTimeoutMs` 3000) |
| 분리 → WAITING (맥북 시각) | **3.72 s** |
| 분리 중 오경고 | 없음: 약 58초 동안 `[RX]` 0, `[ALIVE] ... state=WAITING` 5회 |
| XIAO USB 재연결 (맥북 시각) | 19:49:26.305 (직전 `[ALIVE]` 19:49:26.623 `state=WAITING` → 초기화 확인) |
| 새 `[RX]` + `[LED] ON` + `WAITING -> WARNING` | 19:49:28.755 (`t=99217ms`, rssi −60) |
| 재연결 → WARNING | **2.45 s** (XIAO 부팅 + 시리얼 대기 최대 2초 + 스캔 지연 포함) |
| `scan_errors` | 0 |
| 판정 | 1회 성공. 반복 시험 미실시 |

같은 기록의 이상 사항: 기록기가 포트를 열 때 ESP32 리셋(`rst:0x1 (POWERON_RESET)`), 깨진 줄 2회(그 자리의 `[RX]` 1줄씩 빠짐, 원인 미확인).

## X2. 거리별 RSSI 측정 (경고 판정 시험 아님)

목적: 거리마다 `[RX]` RSSI의 범위·평균·변동을 모아 근접 판단 로직(이동평균·히스테리시스·시간 조건)의 근거를 만든다.
**RSSI는 거리 값이 아니다.** 이 측정으로 임계값을 정하더라도 "이 환경·자세에서의 근접 구간"일 뿐이다. 측정 전에는 임계값을 정하지 않는다.

도구: `scripts/rssi_survey.py` (도로변 펌웨어 변경 없음, 기존 `[RX]` 로그 사용)

### 순서

1. `./scripts/lab.sh ports`로 도로변 포트 확인 후 실행:
   `~/.platformio/penv/bin/python scripts/rssi_survey.py record /dev/cu.usbserial-0001 --seconds 30`
   포트를 열면 ESP32가 리셋될 수 있다(관찰 2회/4회). 프롬프트가 뜬 뒤 5초 기다린다.
2. 기준선: XIAO OFF(배터리 분리), 이름 `off` → 30초. 기대: 표본 0.
3. XIAO ON, 0.5m에 놓고 물러나서 5초 뒤 `0.5m` 입력 → 30초 동안 움직이지 않는다.
4. 1m, 2m, 3m, 5m 순서로 같은 방법(올라가는 순서).
5. **확장 규칙**: 5m가 `안정`이면 7m, 10m, 15m, 20m 순서로 공간이 허락하는 만큼 계속. 같은 거리에서 `없음`이 나오면 그 거리를 한 번 더 재고, 두 번 다 `없음`이면 확장 중단.
6. 반복: 가장 먼 거리부터 0.5m까지 내려오는 순서로 다시, 이름 뒤에 `-b` (`5m-b`, `3m-b`, …).
7. (선택) 1m·3m에서 XIAO를 90° 돌리거나 가방에 넣고 `1m-rot`, `3m-bag` 등.
8. `q`로 종료 → 회차별 요약표 출력. 파일: `docs/logs/rssi-<시각>.csv`, `-sessions.csv`, `.log`. 다시 보기: `... rssi_survey.py summary <csv>`.

### 요약표 읽는 법

| 열 | 뜻 |
|---|---|
| `n`, `rate` | 표본 수, 수신율 ≈ n ÷ (30초 ÷ 1.1초). 스캔 1회에 최대 1개라 100%가 상한 |
| `maxgap`, `gap>=3s` | 회차 시작·표본·회차 끝 사이 가장 긴 공백, 3초(현재 경고 해제 타임아웃) 이상 공백 수 |
| `verdict` | **안정**: 3초 이상 공백 없음 = 현재 로직이면 경고가 한 번도 꺼지지 않음 / **간헐**: 수신은 했지만 3초 이상 공백 있음 / **없음**: 표본 0 |
| `min p10 med p90 max mean stdev` | RSSI 분포 (dBm) |
| `outl` | 회차 중앙값에서 20dB 이상 벗어난 표본 수(−107 같은 이상치 재현 확인용) |
| `!! reset/scan_error/garbled` | 회차 중 ESP32 리셋·스캔 오류·깨진 줄 → **무효 검토**, 같은 이름으로 재측정(빈 입력 Enter) |

거리 구분: **최대 수신 거리** = `n ≥ 1`이 나온 가장 먼 거리. **안정 수신 거리** = 그 거리와 더 가까운 모든 거리의 모든 회차가 `안정`인 가장 먼 거리.
